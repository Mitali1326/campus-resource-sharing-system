How a request travels: Browser → Gateway (middleware) → the department node that owns the resource (RPC). Before a slot is booked the gateway takes its lock from the elected leader, so two people can never get the same slot. If a slot is taken you can join its waiting list; when it is cancelled the first waiting department receives it automatically. If departments end up waiting for each other in a circle, a deadlock is detected.

    A read-only overview of every department's slots, for students who only want to look. It is served by the REST API (GET /api/v1/departments/<dept>/resources) through a nearby cache server. The first request is a MISS (the department node is asked); later ones are HITs. The browser also sends the ETag back, and when nothing changed the answer is 304 Not Modified. A booking purges the cached copy, so the board never shows stale slots for long.

    Departments share lab notes and reports here. The gateway is the NameNode (it only remembers which blocks belong to a file and where they are); the seven departments are DataNodes that store the blocks. Every file is cut into small blocks and every block is copied to 3 departments, so the file survives the failure of a department server. Analyze keywords runs a MapReduce word count on the nodes that already hold the blocks.

        Campus-wide notices are stored on 3 department servers (replicas). When you post you choose how careful the system must be:
        Strong waits for all 3 servers (safe, but refuses if one is down), Balanced needs 2 of 3, Fast needs only 1 (always works,
        but a reader may briefly see an older notice). This is the CAP trade-off. Try it: stop two department containers, then post with Strong and with Fast.

    Every department node pushes a small “I am alive” beacon to the gateway every 3 seconds. If beacons stop, the gateway first suspects the node (after 7 s) and then declares it dead (after 15 s). Stop a container (docker stop mech-node) and watch this table change by itself.

    The leader (shown as LEADER in the header) is the lock manager for bookings and the miner of the audit trail. Bully: a node that notices a problem challenges every stronger node; the strongest live node wins. Ring: an election token travels around a logical ring collecting ids; the highest id wins. Stop the leader's container, then run an election: a new leader takes over.
    
            
    
              
              
              
              
            
    
            
    
          
    
        
    

        
    
          
    
          
    
            
    Every node's clock is deliberately wrong by a different amount, like real computers (this is why booking times are not compared across servers). Cristian: each node asks one time server (the gateway), measures the round-trip time and sets its clock to the reply plus half the round trip. Berkeley: nobody is trusted; the master collects all clocks, averages them and tells every node how much to adjust.
    
            
    
              
              
              
              
            
    
            
    
            
    
          
    
        
    

        
    
          
    
          
    
            
    Physical time cannot tell which event caused which. The Lamport clock (the LC=n tags on notifications and in the RPC trace) gives every event a number consistent with cause and effect. A vector clock keeps one counter per department and can also tell when two events are concurrent. Every chat message carries one (the VC line under each chat bubble).
    
            
    
              
              
            
    
            
    
          
    
        
    

        
    
          
    
          
    
            
    How do you photograph a system that keeps changing while you look at it? The initiator records its own state and sends MARKER messages. Each node records its state when the first marker arrives and then records every message still travelling on its other channels (in-flight messages). The result is a consistent picture of the whole campus (Chandy–Lamport).
    
            
    
              
              
            
    
            
    
          
    
        
    

        
    
          
    
          
    
            
    Booking a slot is a critical section. Centralised algorithm (really used on every booking): the gateway asks the leader for that slot's lock and waiting requests queue first-come-first-served. Ricart–Agrawala (simulation): no coordinator — every process multicasts a timestamped request and replies are deferred to later requests. The fairness idea of Lodha & Kshemkalyani (self study) is explained in the concepts file.
    
            
    
              
              
              
            
    
            
    
          
    
        
    

        
    
          
    
          
    
            
    This watches the waiting lists of the booking screen. An edge “A waits for B” means department A is on the waiting list for a slot that B holds. A circle of such edges is a deadlock. Knapp classifies detection algorithms as path-pushing, edge-chasing, diffusion and global-state; here you can run a wait-for graph cycle search and the Chandy–Misra–Haas probe algorithm. “Create sample deadlock” makes two real bookings and two crossing waiting-list entries for you.
